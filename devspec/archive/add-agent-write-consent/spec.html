MCP agent write consent — per-token opt-in gate
ContextProposalArchitecture ImpactBackendFrontend TasksCoverage

Context

add-agent-write-consent status: pending (not yet on board) depends_on: [] skills: frontend-design

Agent MCP write tools stay blocked unless the token owner explicitly consents at create time.

Proposal

External AI agents connect over MCP with a PAT that already carries write scopes. Ticking a write scope is the only gate today — no explicit human-readable consent to act on the owner's behalf. This adds an explicit per-token opt-in checkbox and enforces it: write tools rejected (hard error) unless allowWrite = true.

Delivers

  • Per-token McpToken.allowWrite (default false).
  • Checkbox in Create MCP token modal: "Allow this agent to write data as me".
  • Write-scoped MCP tools rejected with hard error unless consent on. Read tools unaffected.

Out of scope

  • Impersonating other members (actor is always the token owner = self).
  • Per-member / project-wide switch (rejected — see design).
  • Editing consent after creation (revoke + recreate).
Behavior change: existing tokens migrate to allowWrite=false (fail-closed). Write-scoped agents stop writing until re-minted with consent. Accepted by owner.

Architecture

ASCII fallback (archify not invoked).

Create modal (McpAccessCard)
  └─ POST /api/projects/:projectId/mcp-tokens { label, scopes, allowWrite, expiresAt }
        └─ McpTokenController.create → McpTokenService.createToken
              └─ McpToken row { userId=self, scopes, allowWrite }

Agent request
  Bearer PAT → /api/mcp
    └─ McpPatGuard → McpSession { userId, projectId, scopes, allowWrite }
          └─ tool handler → requireScope(session, 'tasks:write')
                ├─ scope not in token.scopes       → "Missing required scope"
                ├─ write scope AND !allowWrite      → "Agent writes not permitted…" (HARD ERROR)
                └─ else → TasksService.create(projectId, session.userId, dto)  [actor = self]

Backend

DB: add allowWrite Boolean @default(false) to McpToken; forward Prisma migration, additive, no backfill.

DTO: CreateMcpTokenDto gains allowWrite?: boolean (@IsOptional @IsBoolean) — required or global forbidNonWhitelisted 400s it.

Gate: single choke point requireScope:

WRITE_SCOPES = { tasks:write, tasks:logtime, tasks:attach, testcases:write, testexec:write }
requireScope(session, scope):
  if scope ∉ session.scopes: throw "Missing required scope: " + scope
  if scope ∈ WRITE_SCOPES and not session.allowWrite:
      throw "Agent writes not permitted: token has no write consent"

Read scopes never in WRITE_SCOPES → read tools untouched. Missing-scope error precedes consent error.

Frontend

Consent block below the Scopes grid in the Create MCP token modal. Reuses <Checkbox>, <Label>, and the existing destructive banner style. Advisory warning when a write scope is ticked but consent off; does not disable Create.
