Data-only edit to the seed constants a new project's TASK workflow is created from.

Proposal

Why. New projects seed Backlog · In Progress · In Review · Done · Blocked. We want the intended lifecycle instead: Received · Assigned · In Progress · Review · Done · On Hold · Rejected · Canceled.

Delivers. On project create, the default TASK workflow seeds these 8 statuses (colors, one default start, three closed) plus a transition graph: linear happy path + on-hold / reject / cancel escapes.

Out of scope. Bug workflow, existing projects (seed is guarded — no backfill), frontend (renders dynamically).

Architecture ASCII fallback

POST /projects → ProjectsService.create
                   ├─ WorkflowService.seedDefaultWorkflow(id)   ← reads DEFAULT_STATUSES / DEFAULT_TRANSITIONS  (THIS CHANGE)
                   │     └─ tx: create workflowStatus[] + workflowTransition[]  (kind: TASK)
                   └─ WorkflowService.seedDefaultBugWorkflow(id) (unchanged)
