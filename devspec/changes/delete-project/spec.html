delete-project

status: not yet planned depends_on: none skills: db, backend, frontend, verify

Proposal

A project owner needs to remove a project that is no longer wanted. Today the only lifecycle action is archive (permission-gated, in-app restore, hides from the active list). There is no "delete" — archive is wrong for "this project should be gone": any member with projectSettings:update can archive/unarchive, and it stays visible under the archived view.

Delivers: a soft delete — an owner-only Danger Zone in Project Settings → General; deleting sets Project.deletedAt; the project then disappears from every member's lists and 404s on detail (owner included); a warning confirm dialog guards it; recovery is DB-only by an administrator.

Scope out

  • In-app restore / deleted-projects view — recovery is DB-only
  • Cascading soft-delete to children — hidden transitively
  • Hard delete / purge; changing archive behavior
  • Ownerless projects — ownerId is NOT NULL

      │  (Danger Zone renders only if user.id === project.ownerId)
      ▼
AlertDialog confirm ──► useDeleteProject (react-query)
      │                       │ DELETE /projects/:projectId
      ▼                       ▼

 out of project          └─► ProjectsService.remove(projectId, req.user.id)
                              ├─ load project
                              ├─ ownerId !== userId ──► 403 Forbidden
                              └─ set deletedAt = now()

Reads now filter deletedAt:
  GET /projects      → findAllForUser → drop m.project.deletedAt (L120, next to archived)
  GET /projects/:id  → findOne        → deletedAt != null ⇒ 404 NotFound
