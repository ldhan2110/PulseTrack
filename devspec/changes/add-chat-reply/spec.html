Proposal

Why

Chat supports send/edit/delete/reactions/attachments/@mentions but no reply to a specific message. Replies read as floating statements with no anchor. Users want to reply and have the UI show which message they replied to.

Delivers

  • Reply from any message — action in the hover toolbar (own + others, DM + channel).
  • Quoted parent — compact preview above the reply body (author + one-line snippet).
  • Composer reply banner — "Replying to <name>: <preview>", cancel via ✕/Escape.
  • Jump to original — click the quote → scroll + highlight flash.
  • Durable — real self-FK on Message; survives reload, rides the broadcast.

Scope — out

  • Threaded/nested sub-thread view (v1 = flat inline quote).
  • Deep-history jump when the parent is in an unloaded page (no-op instead).
  • Reply notifications (mentions cover call-outs).
  • @@index([replyToId]) — no reply-thread query in v1.

Backend

DB — Message.replyToId (self-FK, additive)

replyToId String?
replyTo   Message?  @relation("MessageReplyTo", fields:[replyToId], references:[id], onDelete: SetNull)
replies   Message[] @relation("MessageReplyTo")

Migration: ALTER TABLE "Message" ADD COLUMN "replyToId" TEXT + FK. No backfill, no index. Source: file-derived (no live DB MCP). Full grid in db.md.

DTO

SendMessageDto.replyToId?: string (@IsOptional @IsString).

Service — sendMessage

Validate parent in same conversation (findUnique select conversationId, else 400), create with replyToId, include preview at all 3 read sites:

replyTo: { select: { id:true, body:true, deletedAt:true, author: memberUserSelect } }

Deleted parent (deletedAt != null) → body blanked to "message deleted" (mirrors existing deleted-map @ chat.service.ts:330).
