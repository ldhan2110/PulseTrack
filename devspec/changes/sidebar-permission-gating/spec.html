sidebar-permission-gating

Show/hide project sidebar items by the current role's view permission

Proposal

Why

RBAC already exists: each role carries per-area view/create/update/delete, edited in Settings → Roles & Permissions (RolesPermissionsTab), and the API enforces it on every route (@RequirePermission). But the left project sidebar (AppSidebar) renders every nav item for every member regardless of view — a member with bugs.view = false still sees the Bugs link.

What it delivers

Each project nav item is shown only when the member's role grants view on that item's area; otherwise hidden. The "checked view box" becomes the show/hide switch. System roles keep seeing everything (they bypass all checks).

Scope

In

  • Gate every PROJECT_NAV_ITEMS entry by its area's view via existing usePermissions().can().
  • Map each nav item to an area; "Project Planner" parent shown if any child viewable.
  • Add a new wiki permission area (web + api) so Wiki becomes gate-able + gets a view checkbox.

Out

  • No change to top-level nav (My Tasks, Chat, project switcher, footer).
  • No change to route guards / API enforcement — sidebar visibility only, not the security boundary.
  • No backfill of existing roles' stored JSON for wiki (accepted fail-closed default).
  • No checkbox-grid UI work — RolesPermissionsTab auto-renders the new area.

Architecture

ASCII flow (archify not used — single linear flow).

Member opens project
        │
        ▼
AppSidebar (activeProjectId from uiStore)
        │  usePermissions(activeProjectId).can(area,'view')
        ▼
filterNavByPermission(PROJECT_NAV_ITEMS, can)
        │        ├─ leaf: show if !area || can(area,'view')
        │        └─ parent: show if any child survives
        ▼
render surviving items only
        ▲
        │ role.permissions[area].view   (isSystem ⇒ always true)
   RolesPermissionsTab checkbox grid ── writes ──▶ role.permissions (JSON)
        ▲
   PERMISSION_AREAS (now includes `wiki`)

Blast Radius

  • apps/web/src/components/layout/AppSidebar.tsx — area on NavItem, usePermissions, filter (+ extract filterNavByPermission).
  • apps/web/src/lib/permissions.ts — wiki in RolePermissions + PERMISSION_AREAS.
  • apps/api/src/auth/permissions.ts — wiki in RolePermissions + 3 presets.
  • Auto-affected, no edit: RolesPermissionsTab, PermissionGate/hasPermission.
  • Not touched: API @RequirePermission guards, DB schema/migrations, routing.

Risk

  • Reversibility: high — pure additive.
  • Risk: low-medium — main hazard is over-hiding (wrong map entry / stale role JSON); mitigated by unit test + live verify. Data access unchanged → no security regression.
